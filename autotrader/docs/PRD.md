# PRD: 룰 기반 자동매매 프로그램 (토스증권 Open API)

- 상태: **초안 v0.1**
- 작성일: 2026-10-20
- 대상 독자: 본인(개인 투자자 겸 개발자)

---

## 1. 배경과 문제

- 정해 둔 매매 룰이 있어도 장중에 계속 지켜볼 수 없고, 감정 때문에 룰을 어기게 된다.
- 토스증권이 2026년 8월 Open API를 전체 고객에게 정식 출시하면서, 개인도 국내·미국 주식 주문을 프로그램으로 자동화할 수 있게 되었다.

## 2. 목표

1. 미리 정한 룰에 따라 **사람 개입 없이** 매수·매도 주문을 낸다.
2. 같은 룰 코드로 **백테스트 → 모의(paper) → 실전**을 차례로 검증한다.
3. 버그나 시장 급변이 있어도 **손실이 정해 둔 한도를 넘지 않게** 막는다.

## 3. 비목표 (이번 범위에서 하지 않는 것)

- 수익 보장, 전략 자동 탐색, 머신러닝 기반 예측
- 초단타(초·분 단위 고빈도) 매매
- 여러 사용자용 서비스, 웹 UI
- 옵션·선물·코인 등 주식 외 상품
- 타인 자금 운용 (법적 이슈가 있음)

## 4. 성공 기준

| 단계 | 기준 |
|---|---|
| 백테스트 | 수수료·세금·슬리피지를 포함하고, 최적화에 쓰지 않은 기간(out-of-sample)에서도 **단순 보유 대비** 결과가 납득 가능해야 함 |
| 모의(paper) | 4주 이상 무중단 운영, 의도하지 않은 주문 0건, 모든 주문이 저널에 기록됨 |
| 실전 소액 | 4주 이상 운영, 리스크 한도 위반 0건, 모의 결과와 실제 체결의 차이를 측정·기록 |

단계를 건너뛰지 않는다. 위 기준을 통과해야 다음 단계로 간다.

## 5. 사용 시나리오

1. 사용자가 `config.toml`에 종목, 전략, 리스크 한도를 적는다.
2. `autotrader backtest`로 과거 데이터에서 전략을 검증한다.
3. `autotrader run`(paper)으로 실시간 시세에 가상 체결을 돌린다.
4. 기준을 통과하면 config에 `mode = "live"`로 바꾸고 `autotrader run --live`로 실전을 시작한다.
5. 문제가 생기면 `touch STOP`으로 즉시 주문을 멈춘다.

## 6. 기능 요구사항

### FR-1. 전략
- 전략은 "지금까지의 시세 + 현재 보유 상태"만 보고 매수/매도 신호를 낸다.
- 전략은 증권사 API를 직접 호출하지 않는다 (백테스트와 실전이 같은 코드를 쓰기 위해).
- 새 전략은 `Strategy` 클래스를 상속해 추가한다. MVP 예시: 이동평균 교차.

### FR-2. 리스크 관리 (모든 모드 공통)
| 항목 | 기본값(예시) | 동작 |
|---|---|---|
| 1회 매수 최대 금액 | 50만 원 | 수량 = floor(min(한도, 현금) / 가격) |
| 최대 보유 종목 수 | 3 | 넘으면 신규 매수 거부 |
| 하루 최대 매수 횟수 | 5 | 버그로 인한 연속 주문 방지 |
| 일일 손실 한도 | 당일 시작 평가금의 3% | 넘으면 신규 매수 중단 (매도는 허용) |
| 추가 매수(물타기) | 하지 않음 | 보유 종목 재매수 거부 |
| 비상 정지 | `STOP` 파일 | 존재하면 매수·매도 모두 중단, 루프 종료 |

### FR-3. 백테스트
- 일봉 기준. i번째 봉 종가로 신호 → **i+1번째 봉 시가로 체결** (미래 데이터 참조 방지).
- 수수료, 매도세, 슬리피지 반영.
- 출력: 총 수익률, 연환산 수익률, MDD, 거래 횟수, 승률, **단순 보유 수익률(비교 기준)**.

### FR-4. 모의(paper) 운영
- 시세는 토스 API에서 실시간으로 받고, 주문만 가상으로 체결한다.
- 토스가 모의투자 계좌를 제공하는지 확인되지 않아서 자체 구현한다.

### FR-5. 실전 운영
- 실전 주문은 **config의 `mode = "live"`와 `--live` 플래그가 둘 다 있어야** 실행된다.
- 정규장 시간에만 동작한다.
- 주문 요청은 자동 재시도하지 않는다. 응답이 불확실하면 주문 목록을 조회해 확인한다 (중복 주문 방지).

### FR-6. 기록과 알림
- 모든 신호, 리스크 판단, 주문 결과를 `logs/journal.jsonl`에 한 줄씩 남긴다.
- (M3) 주문 체결, 오류, 손실 한도 도달 시 텔레그램 등으로 알림을 보낸다.

## 7. 비기능 요구사항

- **보안**: API 키(client_id/secret)는 환경변수로만 주입하고 코드·config·git에 넣지 않는다. 토스 API는 허용 IP 등록이 필요하므로 고정 IP 서버에서 운영한다.
- **안정성**: 한 종목의 오류가 전체 루프를 멈추지 않는다. 일시적 오류(429/5xx)는 지수 백오프로 재시도한다 (주문 제외).
- **호출 한도 준수**: 호출 사이에 최소 간격을 둔다. 정확한 한도는 공식 문서로 확인한다.
- **운영 환경**: 상시 켜져 있는 서버(VPS 등)가 필요하다. 클라우드 세션이나 노트북은 부적합하다.
- **테스트**: 전략, 리스크, 백테스트, 브로커 공통 로직은 단위 테스트로 검증한다.

## 8. 시스템 구조

```
            ┌──────────────┐
 config ──▶ │ TradingEngine│ ── 저널(JSONL), 로그
            └──────┬───────┘
     시세 ◀────────┼────────▶ 주문
  MarketData   Strategy → RiskManager   Broker
  (TossClient)   (신호)     (수량·한도)   (PaperBroker | TossClient)
```

| 모듈 | 파일 | 상태 |
|---|---|---|
| 데이터 모델 | `models.py` | 완료 |
| 전략 | `strategy/` | 예시 1개 완료 |
| 리스크 관리 | `risk.py` | 완료 |
| 백테스트 | `backtest.py` | 완료 (단일 종목, 일봉) |
| 가상 체결 | `broker/paper.py` | 완료 (메모리 상태) |
| 토스 클라이언트 | `broker/toss.py` | **공통부(토큰, 재시도, 호출 간격)만 완료. 엔드포인트는 공식 문서 확인 후 구현** |
| 실행 루프 | `engine.py` | 완료 |
| CLI | `cli.py` | 완료 |

## 11. 설계상 결정과 그 이유

- **일봉 전략을 장중 루프로 돌리면** 당일 봉이 미완성이라 신호가 하루에도 여러 번 바뀔 수 있다. 백테스트(다음 날 시가 체결)와 실전 동작이 달라지는 원인이 된다. → M1에서 "장 마감 직전 1회 실행" 또는 "다음 날 장 시작 시 1회 실행" 중 하나로 맞춘다. **결정 필요.**
- **매도는 손실 한도와 무관하게 허용**: 한도에 걸렸을 때 포지션 정리까지 막으면 오히려 위험하다.
- **주문 자동 재시도 금지**: 네트워크 오류 뒤 재전송은 이중 주문의 가장 흔한 원인이다.

## 12. 위험과 대응

| 위험 | 대응 |
|---|---|
| 백테스트 과최적화 | out-of-sample 검증, 파라미터 수 최소화 |
| 코드 버그로 연속 주문 | 일일 매수 횟수 한도, 비상 정지 파일, 소액 시작 |
| API 장애 / 스펙 변경 | 오류 시 주문하지 않고 기록·알림, 공식 공지 확인 |
| API 키 유출 | 환경변수, IP 화이트리스트, 주기적 재발급 |
| 서버 다운 중 급락 | 증권사 앱의 조건주문(스탑로스)을 병행 고려 |
